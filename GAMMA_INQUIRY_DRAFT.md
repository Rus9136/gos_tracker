# Черновик запроса в Gamma Technologies (трек 3, раздел 6.2)

> Цель письма — выяснить легальный серверный/headless путь для ГОСТ-шифрования
> ценового предложения на goszakup.gov.kz (функция `EncryptOfferPrice`), которое
> сейчас выполняется десктопным Tumar CSP через CryptoSocket (`wss://127.0.0.1:6127`).
> Контакты: gamma.kz/contact, gamma.kz/support; УЦ — ca.gamma.kz, ca.kisc.kz.
> Файлы на ca.kisc.kz/downloads: `SDK.zip` (dev-комплект), `ws_doc.zip`
> (спецификация веб-сервиса Tumar), `SetupCryptoSocket.zip`.

**Тема:** Серверный режим Tumar CSP / CryptoSocket для автоматизации подачи ценовых предложений на goszakup.gov.kz

Здравствуйте!

Мы разрабатываем серверную систему автоматизированной подачи тендерных заявок
на портал государственных закупок РК (goszakup.gov.kz) от имени клиентов, по их
письменному согласию и с их ЭЦП-ключами. Этап подачи ценового предложения на
портале использует ваш продукт **Tumar CSP** (CryptoSocket, `wss://127.0.0.1:6127`,
функция `EncryptOfferPrice`) для ГОСТ-шифрования цены «конвертом» на сертификат
тендера (УЦ EFC). CMS-подпись мы уже выполняем серверно.

Просим проконсультировать по следующим вопросам:

1. **Серверный / headless / Linux-режим.** Существует ли серверная или Linux-версия
   Tumar CSP, либо серверный режим CryptoSocket, пригодный для работы без
   графического десктоп-окружения (в Docker/systemd)?

2. **SDK и спецификация веб-сервиса.** Как получить доступ к `SDK.zip` и `ws_doc.zip`
   (спецификация веб-сервиса Tumar)? На каких условиях (лицензия, NDA, договор)?
   Есть ли C/Java/.NET API или REST-интерфейс к функциям провайдера?

3. **Неинтерактивный `EncryptOfferPrice`.** Сейчас число цены вводится оператором в
   нативном GUI-окне Tumar CSP и не передаётся по websocket. Есть ли неинтерактивная
   (программная) форма функции `EncryptOfferPrice`, принимающая значение цены
   параметром — для полностью автоматической подачи без участия человека?

4. **Формат конверта.** Можно ли получить спецификацию формата результата
   `EncryptOfferPrice` — полей `encryptData`, `encryptKey` (CryptoAPI SIMPLEBLOB),
   `salt`, `sign`, `info`: какой алгоритм key-transport, какой paramset wrap-шифра,
   как формируется поле `sign` (над чем считается) и `salt`?

5. **Серверная лицензия `apiKey`.** Функции EFCAPI требуют валидного `apiKey`
   (`SetAPIKey`). Как оформляется серверная лицензия для автоматизированного
   использования, каков срок и порядок продления?

6. **Версионный гейт.** Портал проверяет версию провайдера (наблюдали `1.0.13.2286`).
   Как обеспечивается совместимость версии при серверном развёртывании, учитывая
   обязательность обновления криптосокета (с 16.04.2026 — блокировка подачи при
   неактуальной версии)?

Готовы подписать NDA и обсудить коммерческие условия серверной лицензии.
